Methodology

The FastAPI TestClient (httpx-based) was used, which runs requests in-process without network overhead. Results reflect SQLite query execution + Python serialization + Pydantic validation time.

Slowest Endpoint Analysis

1. Screener (15.1ms avg) — The slowest endpoint reads from an Excel file (screener_output.xlsx) on every request via openpyxl.load_workbook(). Each call re-opens the workbook, iterates all rows, and closes it. This file I/O is 5-7x slower than SQLite-backed endpoints. Bottleneck: repeated file I/O (Excel parsing).
2. Market Cap (7.0ms avg) — Performs a 3-way JOIN across market_cap, companies, and sectors tables, then sorts by market_cap_crore DESC. The sort on a non-indexed column adds overhead. Bottleneck: multi-table JOIN + sort.
3. Ratios (5.0ms avg, P95: 34.8ms) — The P95 spike is from Python/Pandas import overhead on first calls. The median (3.4ms) is representative. Bottleneck: import-time variance.

Index Assessment

No new indexes are required. All API queries are covered by existing indexes. The UNIQUE constraints on (company_id, year) in financial_ratios, profitandloss, balancesheet, cashflow, market_cap, and documents tables act as implicit composite indexes. With only 92 companies, even full table scans complete in under 1ms.
Optional optimization: A composite index on peer_percentiles(peer_group_name, year) could marginally improve the peer compare endpoint by avoiding a sort after the group filter. However, with 560 total rows in the table, the benefit is negligible and is not recommended.

API Client Verification

All 17 client functions verified. The Streamlit integration client (src/api/client.py) was tested against a live FastAPI server. All functions return correct data types and values. The client communicates correctly with the API.

Limitations

  • TestClient runs in-process — no network latency, TLS, or connection pooling overhead.
  • Sequential requests only — no concurrency or connection pool pressure.
  • 20 iterations per endpoint — sufficient for median/P95 but not for statistical rigor.
  • Single-machine benchmark — does not reflect multi-user or production deployment scenarios.
  • No load testing — these are latency measurements, not throughput or stress tests.
